# 关键决策用户确认机制

## 适用场景

- **初始建模**（重点）：假设的提出与取舍、模型选取、数据口径确定。
- 求解与实现中的关键决策：参数设定、方案取舍、阈值确定。
- 任何用户未明确授权自行决定、但影响结果方向的事项。

## 交互形式（选项式）

AI 先提出方案（必须附理由，必要时附备选方案），然后给出选项，等待用户选择：

```
方案：……（理由：……）
请选择：
1. 是     —— 按此方案执行
2. 否     —— 你给出方向，我调整后再次提出方案供你确认
3. 其他   —— 你自由输入修改意见，我按意见调整后回到选项
```

对应关系：

| 选项 | 用户含义 | AI 动作 |
|---|---|---|
| 1. 是 | 认可方案 | 按方案执行 |
| 2. 否 | 方向不对 | 根据用户给出的方向调整，重新提出方案并再次确认 |
| 3. 其他 | 部分修改/补充 | 按用户输入调整方案，调整后回到选项（或直接执行明确的修改意见） |

## 执行规则

- **必须等用户选择后才能进入下一步**，不得替用户决定或跳过确认；用户对某个决策已明确授权"你自己定"时，可自行决定但须记录授权。
- 方案必须给出理由；存在合理备选时给出备选及其适用条件，帮助用户判断。
- 确认结果（含用户修改意见）记录到 `plan.md` 或契约文档（假设清单、题目分析报告等），作为后续工作的依据。
- 机制只增加确认环节，不改变建模与求解本身的工作方式。

## 与现有流程衔接

- **阶段 0（建模前置）**：假设提出与取舍、模型选取、数据口径等契约冻结前，逐项走确认机制；契约冻结的前提是用户已确认。
- **求解中**：关键参数与方案取舍走同一机制。
- **双解题手模式**：两解题手共同裁决的前提是用户已授权；涉及假设、模型、阈值裁决等关键决策，先经用户确认再冻结。
