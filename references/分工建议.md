# 解题手分工建议（协同 / 独立灵活机制）

## 触发时机

双解题手模式**阶段 0 阅读完整题之后、进入建模之前**完成依赖结构判定，选择协同/独立模式，给出分工建议，经用户确认后写入契约。

## 第一步：依赖结构判定（决定模式）

完整读题后，画出子问题依赖图：

- 每个问是否被后续问直接引用（模型复用 / 结果承接 / 参数共享）。
- 统计**基础问数量**（被后续问依赖的问，可不止一个）：
  - **0 个基础问**（各问相互独立或仅共享数据）→ 完全独立模式。
  - **1 个基础问** → 协同 + 独立混合模式。
  - **多个基础问 / 链式依赖**（Q1→Q2→Q3 逐层承接）→ 协同为主模式。

## 第二步：模式选择（随依赖结构自适应）

| 模式 | 适用 | 机制 |
|---|---|---|
| **完全独立** | 无基础问，各问相互独立 | 按题号分配，两人各自独立完成建模→求解→出图；仅共享契约与结果锚点对账 |
| **协同 + 独立混合** | 存在 1 个基础问 | 基础问两人**共同实现**（双实现 + 交叉验证），其余独立问按题号各认领 |
| **协同为主** | 链式/多基础问 | 分段协同：承接链共同实现（强者主导前段、弱者跟进后段并交叉验证），末端独立问仍可独立；协同问数量由依赖强度决定 |

模式的共同底料（所有模式都保留）：

- **轻度协同**：共享契约冻结（题目分析报告、术语表格、假设清单、符号表、数据口径）+ 阶段 2 结果锚点对账。
- **协同机制**（共同实现的问）：双实现 + 交叉验证——两人各自独立实现，结果一致作为交叉验证证据，有偏差则对齐口径后复算；两种实现均保留在工作区，合稿择优或合并表述。
- **独立机制**（各认领的问）：工作区物理隔离，只写自己目录；互不阻塞，仅在契约与锚点上对齐。

## 第三步：实力分配

两人实力不同（一强一弱）时：

- 实力较强一方：主导协同问（基础问/承接链）的实现，并承担较难的独立问。
- 实力较弱一方：承担较简单的独立问，并参与协同问的交叉验证与实现（顺带熟悉口径，便于独立问衔接）。
- 实力对比由用户提供或从历史项目推断，最终分配**必须经用户确认**（见 `决策确认机制.md`）。

## 第四步：输出并确认

产出分工建议，走用户确认机制后冻结写入 `00_契约/`（或 `plan.md`）：

```
分工建议
- 依赖结构：Qx 被 Qy/Qz 依赖（基础问）；其余相互独立
- 模式：协同 + 独立混合（基础问共同实现）
- 协同问：Qx → 两人共同实现，A 主导
- 独立问：Qm → 解题手 A；Qn → 解题手 B
- 依据：依赖判定 + 实力分配
```

## 思路与代码开放原则

两解题手的全部思路文档（题目分析、假设、求解报告）与代码、结果表、图表对论文手（合稿方）**全程开放**：合稿阶段可读取两份工作区全部产物，不得以"我的部分"为由拒绝查看或遮挡实现细节。协同问的两种独立实现均保留在各自工作区，合稿时择优或合并表述。

## 结果锚点对账（实现方式）

承接问（以队友结果为基础的后续问）按以下方式对账，**不重算队友结果**：

- **直接读取交付文件**：把队友交付的 csv/json 结果文件（如 `q1_decision_table.csv`、`q1_wait_stats.csv`）作为输入常量读入自己代码，不在自己代码里重算队友的数值——确保解题基础完全建立在队友最新结果之上（2019 C 题教训：Q3/Q4 直接读取 Q1/Q2 交付文件的 $\lambda_{\max}$、$W^*$、$n^*$ 等数值）。
- **对账时机**：进入建模前核一遍关键数值（确认可读、量纲/口径一致）；求解完成后与锚点再核一遍；不一致立即停下对齐口径，不带着错误锚点往下写。
- **锚点变更**：队友交付文件更新后，先复核差异再决定是否重新对账，避免静默沿用旧值。
