> 用户明确要求（2026-08-14）：**代码阶段预估工作量太大时，skill 有义务提醒用户可以在 AutoDL 上跑，并给出选取公共镜像的建议。** 本建议在 `3coding-visual` Step 1/2 之间执行；`2analysis-modeling` 任务清单冻结时也可预告。

## 一、什么时候必须提醒（工作量评估标准）

满足任一条即向用户**主动提醒**（交互知情机制知情层），并给出本建议：

- **预计运行时长 ≥ 30 分钟**（大规模仿真：蒙特卡洛 M 上万次、网格搜索参数空间大、逐日/逐小时级长时序滚动预测）。
- **需要 GPU 或大内存**：深度学习/大模型训练、神经网络、大规模矩阵运算；本地显存/内存不足。
- **本地环境不满足依赖**：缺少关键库（如 statsmodels、pulp、torch）、Python 版本不匹配、装依赖会污染本地环境。
- **数据量级大**：附件数据 GB 级、多文件批量处理、多次往返读取。
- **并发/并行需求**：多子问题同时跑、交叉验证 K 折全量重复。

判断依据来自建模报告的任务清单与算法复杂度（`2analysis` Step 5），不要等到代码写了一半才发现。

## 三、AutoDL 公共镜像选择建议

选镜像的四个要素：**框架版本 → CUDA 版本 → Python 版本 → 预装环境**。

### 1. 按任务类型选

| 任务类型 | 建议镜像 | 理由 |
|---|---|---|
| 深度学习/大模型/神经网络 | PyTorch 2.x（CUDA 11.8 或 12.1）/ TensorFlow 2.x | 训练/推理要 GPU；框架版本匹配代码 |
| 大规模科学计算/仿真/优化 | 纯 CPU 镜像（基础镜像 + scipy/sklearn/statsmodels/pulp） | 蒙特卡洛、网格搜索、LP/IP 多数 CPU 即可，选 GPU 反而浪费 |
| 数据清洗/预处理/EDA | 预装 pandas/numpy/matplotlib 的数据科学镜像 | 即开即用，无编译等待 |
| 混合（预处理+少量训练） | 数据科学镜像 + 按需 `pip install torch` | 先跑通 CPU 流程再上 GPU |

### 2. 四个要素的选取要点

- **框架版本**：与代码一致（如代码按 `statsmodels` 0.14 写，选带对应版本或允许 `pip install -r requirements.txt` 覆盖的镜像）；PyTorch 2.x 首选，兼容性最好。
- **CUDA 版本**：与实例显卡驱动匹配；AutoDL 常见 CUDA 11.8 / 12.1，优先选镜像标注的默认版本，避免自己装驱动。
- **Python 版本**：优先 3.10/3.11（本队课件与主流库均兼容）；不要选 3.8 以下或 3.12+ 的冷门版本。
- **预装环境**：优先带 JupyterLab 的镜像（可交互调试、可视化查看）；确认是否预装 sklearn/statsmodels/pulp（未装则用 `pip install -r requirements.txt` 补）。

### 3. 工程纪律（上云前必做）

- 先在本地用 `pip freeze > requirements.txt` 导出依赖清单，随代码上传，镜像内 `pip install -r requirements.txt` 复现。
- 上传前在本地跑通最小样例（小数据/降采样），确认代码无路径硬编码（AutoDL 路径与本地方可不同）；数据与输出目录用相对路径或环境变量。
- 大数据上传用 AutoDL 文件传输/网盘中转，注意按量计费与存储费用。
- 跑完及时关机释放实例（按量计费），结果与中间数据下载回本地，保证论文数值可复现。

## 四、与本地环境的关系

- AutoDL 实例与本队本地 conda 环境（densecaps/shumo）**不必一致**，只要 `requirements.txt` 可复现即可；论文可复现性以代码+requirements 为准。
- 云端跑出的结果**必须下载回本地**并写入 `reports/RESULTS_REPORT.md`（数值一致性门禁不区分云端/本地）。
